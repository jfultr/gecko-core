# Gecko: прогресс цикла разработки

Версия 0.1 · 23 октября 2026 года

[Цикл и понятия](0-concepts/index.md#12-development-cycle) · [Mesh / App](1-mesh-app/model.ru.md)

План отслеживает проход по архитектурным уровням для 1.0.0. На спуске уточняем требования к нижним уровням, постепенно доходя до предметных контрактов. Достигнув нижнего уровня выбранного сценария, разворачиваемся: проводим реальные эксперименты, пишем код и поднимаемся, уточняя каждый уровень по полученным результатам. Направления 2.0.0 и 3.0.0 сохраняют перспективу, но не расширяют обязательства этого прохода.

**Текущее положение:** границы версий Mesh / App определены на уровне модели; следующий шаг спуска — Gecko / Axis. Обратный проход ещё не начат. Этот статус описывает работу по данному плану, а не наличие или отсутствие кода во всём репозитории.

## 1. Маршрут и результаты

Порядок документов задаёт исходный маршрут исследования, а не строгую иерархию исполнения: Line / Point / Edge / View и Block / Anchor связаны контрактами. Если потребуется углубление в конкретный runtime, адаптер или транспорт, добавляем соответствующий шаг до разворота. Базовые операции должны иметь достаточно конкретные контракты, чтобы эксперимент можно было выполнить и оценить.

| Шаг | Направление и уровень | Ожидаемый результат | Статус |
|---|---|---|---|
| D0 | Цели и понятия | Определение feature delivery latency, границы версий и правила прохода | Зафиксировано в документах |
| D1 | Вниз: Mesh / App | Объём 1.0.0, направления 2.0.0/3.0.0, требования к нижним уровням, отдельный список возврата | Зафиксировано на уровне модели |
| D2 | Вниз: [Gecko / Axis](2-gecko-axis/model.ru.md) | Обнаружение, локальные операции, факты, проверки и требования к исполнению | Следующий шаг |
| D3 | Вниз: [Line / Point / Edge / View](4-line-point-edge-view/model.ru.md) | Поддержанный состав обработки, интерфейсы, lifecycle, данные, диагностика и реакции | Не начато в этом цикле |
| D4 | Вниз: [Block / Anchor](3-block-anchor/model.ru.md) и необходимые механизмы | Предметные контракты поставщиков и зависимостей, владение, подготовка и освобождение; конкретные границы экспериментов | Не начато в этом цикле |
| T | Разворот на нижнем уровне выбранного сценария | Выбраны проверяемые гипотезы, входы, критерии результата и минимальные контракты для кода | Не начато |
| U4 | Вверх: базовые механизмы и Block / Anchor | Эксперименты, код, проверенные контракты и ограничения | Не начато |
| U3 | Вверх: Line / Point / Edge / View | Работающая локальная обработка и подтверждённые правила её использования | Не начато |
| U2 | Вверх: Gecko / Axis | Проверенные обнаружение, диагностика, управление и интеграция с нижними слоями | Не начато |
| U1 | Вверх: Mesh / App | Уточнённые решения из раздела 2, интеграция и проверенный сквозной сценарий 1.0.0 | Не начато; вопросы возврата ожидают этот шаг |
| U0 | Проверка цели | Оценка пути от задачи до проверенной функциональности, выявленные ограничения и следующий проход | Не начато |

Для каждого шага сохраняем ссылки на изменения документов, эксперимент или код, наблюдаемый результат и ограничения. Решение на бумаге не означает проверку реализацией. Если эксперимент опроверг предположение, корректируем затронутые контракты и требования, отражаем возврат в прогрессе и продолжаем проход; не сохраняем неподтверждённое обещание ради прежнего плана.

## 2. Что ещё потребуется решить, чтобы описание 1.0.0 стало достаточно определённым для реализации

**Отдельный список возврата на Mesh / App, шаг U1.** Сейчас эти вопросы не требуется закрывать до перехода к Gecko / Axis. На спуске передаём необходимые требования вниз; нижние слои конкретизируют собственные контракты. На обратном проходе собираем подтверждённые результаты и на их основе уточняем решения Mesh / App. Ранние наблюдения можно записывать здесь без объявления вопроса решённым.

| ID | Вопрос возврата | Результат на шаге U1 | Статус |
|---|---|---|---|
| R1 | Минимальная схема App, ревизии и перечень поддержанных операций | Согласованные описание композиции, версии и API локального App | Ожидает обратного прохода |
| R2 | Конкретный состав возможностей сквозного сценария: Points, соединения, Blocks, входы и результат | Проверенный минимальный набор и его ограничения | Ожидает обратного прохода |
| R3 | Правила изменения, остановки, удаления и очистки локального App | Предметные переходы, владение ресурсами и безопасные явные действия | Ожидает обратного прохода |
| R4 | Форматы запросов, отчётов, идентификаторов и адресация API | Типизированные контракты, согласованные с нижними слоями | Ожидает обратного прохода |
| R5 | Хранение ревизий, разрешений исполнения, учёта запросов и последних отчётов | Проверенные механизмы сохранения, публикации и восстановления, политика хранения | Ожидает обратного прохода |
| R6 | Условия готовности, тайм-ауты и поведение после перезапуска | Проверенные условия допуска, ожидания и восстановления локальных операций | Ожидает обратного прохода |
| R7 | Минимальный профиль Zenoh и проверки его гарантий | Выбранные SDK, ключи, настройки и подтверждённые гарантии обмена | Ожидает обратного прохода |
| R8 | Критерии приёмки полного локального цикла | Воспроизводимый сценарий, проверки ошибок и оценка feature delivery latency | Ожидает обратного прохода |
